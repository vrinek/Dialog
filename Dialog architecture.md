# Dialog architecture
## Layer 1
IOTA-inspired blockchain. Multiple threads, each owned by one publisher. “What we heard”.
## Layer 2
Entire graph of all subscribed layer 1. Contains ontology data, edits, attestations. Append only. “What we know”.
## Layer 3
Ontology distilled from layer 2. “What we accept”. This is the ground truth data of our application. It can be read as is, or viewed as SQL.
## The application
It reads from layer 3, but to write it needs to make a roundtrip. It needs to send its updates to the blockchain node and allow the transformations to reach layer 3 before it sees its updates.
## Blockchain node
Responsible for layer 1. Connects to other nodes to push/publish and pull/subscribe new signed blocks of data. A block references the last tip of the same author’s blockchain, and can optionally reference foreign blocks. The subgraph generated by a blockchain needs to be fully valid.
## Atoms, bonds & molecules
The basic building blocks of the ontology graph are atoms, bonds and molecules.
An atom is a node, an entity, a single point of reference. For example `Paris, the capital of France` is one atom, and `Paris Hilton` is another. Each atom needs to be unambiguous and clearly distinguishable from every other atom. It’s important to note that `Elon Musk` and `@elonmusk on X` are two different atoms. One is a human, the other is an X account.
A bond is essentially a sentence template, eg `_A_ is the capital of _B_`. The variables in a bond can be filled in with atoms to make molecules.
A molecule is a complete sentence. It is a bond filled with atoms, eg `[Paris] is the capital of [France]`. A bond can also be filled with molecules, eg `([Elon Musk] founded [Tesla, Inc]) before ([Elon Musk] founded [OpenAI])`.
## Files & scalars
A bond’s variables can also be filled with files or scalars.
A file is any unique, non-interpreted node, that does not represent an identity. For example, an X post is a file, but the X account that posted it is an atom.
A scalar is a numeric value. It can either be a unit-less number, a number with a unit (the unit is an atom), or a datetime range. There are no dates in Dialog. The date `Thursday, Feb 19, 2026` is represented as the datetime range from 00:00 till 23:59 of that date.
## Meta bonds & molecules
Most molecules represent data or relations between data. Some molecules represent states of data. For example if two atoms are created, `Paris, France` and `Paris, the city in France`, a meta molecule can declare that `[Paris, France] is the same as [Paris, the city in France]` and effectively declare a transitive equality between the two. More examples: `_A_ is true`, `_A_ is untrue`, `_A_ contradicts _B_`. These meta molecules are present in layer 2 but applied on layer 3 depending on the application’s subscriptions.
## Authorship
Every block in layer 1 is signed by its author. All the graph data in layer 2 carry the same authorship from layer 1.
## Author subscriptions
A user can subscribe to any amount of authors. Only data from these authors are accepted from layer 2 to layer 3. Any conflicts are flagged for manual intervention (eg when one subscribed author flags a molecule as true and another as untrue).
## Blockchain subscriptions
A user subscribes to at least every blockchain of every author they subscribe to. When a block references a foreign (non-subscribed) blockchain’s block, the history of that blockchain up to the referenced foreign block is also loaded and added to layer 2.
## Private blockchain
Most data in Dialog is expected to be publicly readable. Every user also has a private blockchain that is shared, securely, with only a set list of other blockchain nodes. This is useful to store personal data, shared amongst the devices of one user.
This blockchain is also incorporated into the layer 2 ontology graph.
