# Go reference implementation — design and plan

**Status:** complete
**Date:** 2026-08-12

## Purpose

First executable implementation of the Dialog protocol. Its primary deliverable is not the library itself but a **canonical conformance test-vector suite**: known entities and blocks with their exact dCBOR bytes, digests, CIDs, and signatures. That suite becomes the interop contract for every future implementation. A secondary goal is to surface spec bugs that prose review cannot — any ambiguity found during implementation gets filed as a `todos/` entry.

## Decisions

- **Language:** Go 1.24 (via `nix shell nixpkgs#go`; no system-wide install).
- **Location:** `go/` subdirectory of this repo, module path `github.com/vrinek/Dialog/go`.
- **Dependencies:** zero third-party except `golang.org/x/crypto` (XChaCha20-Poly1305, HKDF, X25519). CBOR is hand-rolled: Dialog's deterministic profile (spec/03) is a small restricted subset — definite lengths only, sorted map keys, shortest ints, no floats, no booleans, and tag 4 as the only tag — and a dependency-free implementation is easier to port and audits the spec more honestly than a general-purpose library would.
- **CID/digest split** per spec/03 "Internal references": `Digest = [32]byte` everywhere inside structures; 36-byte CID only at the API/display boundary.
- **Test vectors:** language-agnostic JSON files (hex-encoded bytes) under `vectors/` at repo root, generated by `go/cmd/genvectors`, committed. `go test` verifies the implementation against the committed vectors (round-trip guard).

## Package layout

```
go/
  dcbor/      Deterministic CBOR: encode Go values (maps/arrays/ints/strings/bytes/null)
              per Dialog's profile; a strict decoder/validator that rejects any
              non-canonical input (wrong key order, non-shortest ints, floats, tags,
              indefinite lengths, duplicate keys).
  cid/        Digest (32 bytes) and CID (36 bytes) types; construction from dCBOR
              bytes; parse/format; parameter validation (0x01 0x71 0x12 0x20).
  entity/     Atom, Bond, Molecule, Filler (typed union: atom/bond/molecule ref,
              IPFS URI, scalar). Canonical dCBOR encoding + digest for each.
  block/      Public/private/rotation block structs; the four operations; signing
              input with "dialog-v1-block" domain separator; Ed25519 sign/verify;
              chain validation (prev linkage, genesis, fork detection); refs
              reachability validation for operations.
  privacy/    Private block payload: encrypt/decrypt refs+ts+ops with
              XChaCha20-Poly1305 (AAD per spec/04), per-recipient key wrap via
              X25519 + HKDF-SHA-256.
  cmd/genvectors/  Emits the conformance vectors to vectors/.
```

L2/L3 (graph accumulation, subscription filtering, meta-bond semantics) come after the wire format is locked — they are pure functions over validated blocks and don't affect the conformance vectors.

## Phases (one commit or more per phase)

1. Scaffold: go.mod, directory layout, CI note. ✔ this doc
   — **done:** module `github.com/vrinek/Dialog/go`, Go 1.24, one dependency.
2. `dcbor` + `cid` with tests — must reproduce the worked example in spec/03 (atom "France" → CBOR `a16b...`, digest `e57761...`).
   — **done:** encoder, strict decoder and fuzz targets; the spec's worked example reproduces byte for byte.
3. `entity` + `block` with tests: signing, chain validation, fork detection.
   — **done:** all three entity types with the meta-bond library, the four operations, reachability validation, key rotation and succession.
4. `privacy` with tests: AEAD round-trip, key wrap, tamper rejection.
   — **done:** XChaCha20-Poly1305 with the spec's AAD, X25519 + HKDF key wrap, small-order key rejection.
5. `cmd/genvectors` + committed `vectors/` + CI runs `go test` + AGENTS.md/README updates.
   — **done:** 159 cases across four files, a conformance test that fails when code and vectors drift, a `go.yml` workflow that regenerates and diffs them, and the dual-tagging release rule (`vX.Y.Z` and `go/vX.Y.Z`) documented in the README.

## Outcome

The vector suite is the deliverable and it exists: `vectors/dcbor.json`,
`entities.json`, `blocks.json`, `privacy.json`, with `vectors/README.md` as the
index. The secondary goal held too — implementing the spec surfaced enough
ambiguity to fill `todos/030` through `todos/048`, every one of them a question
prose review had not raised.

L2/L3 (graph accumulation, subscription filtering, meta-bond semantics) remain
unimplemented, as planned: they are pure functions over validated blocks and
add nothing to the wire format the vectors pin.

## Rules for implementing agents

- The spec (`spec/*.md`) is normative. Code follows spec; never silently "fix" the spec in code. If the spec is ambiguous, incomplete, or wrong: implement the most defensible reading, and file a `todos/NNN-pending-*.md` entry describing the ambiguity.
- Run `go vet` and `go test ./...` before every commit. Go binary: `nix shell nixpkgs#go --command go ...`.
- Commit granularly with conventional-commit messages.
